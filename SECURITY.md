# Security Policy

## Reporting a vulnerability

Please report security concerns responsibly. Do not publish exploit instructions, private data, credentials, or details that could put users at risk in a public issue.

To report a suspected vulnerability, contact the repository maintainer through GitHub's private contact options. If private contact is not available, open a minimal public issue asking for a private reporting channel without including exploit details.

Include, when safe to do so:

- The affected file or feature.
- The potential impact.
- Steps to reproduce at a high level.
- Any suggested mitigation.

## Scope

Security concerns may include script injection, unsafe handling of imported text or files, unintended external requests, exposed secrets, or a vulnerability that could compromise a user's device or information.

## Response

The maintainer will review reports as promptly as circumstances permit. This is a small project and no guaranteed response or remediation timeline is promised. Please allow time to investigate before disclosing details publicly.

## Supported versions

The current default branch is the primary development target. Older snapshots may not receive fixes.
